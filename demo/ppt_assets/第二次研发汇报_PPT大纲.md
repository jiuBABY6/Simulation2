# 第二次研发汇报 PPT 大纲

## 一、汇报定位

### 建议题目

**突发事件网络舆情多 Agent 仿真系统**  
**第二阶段研发汇报：现实机制建模与工程实现**

### 核心叙事

第一次汇报回答的是“系统能否跑通”。第二次汇报重点回答两个问题：

1. 现实中的个体差异、信息不对称、舆论传播、官方回应和时间演化，如何被抽象成可运行的仿真机制。
2. 这些设计如何通过 Persona、评论池、Agent 决策、社交网络、实验编排、状态存储和可视化落地。

本次汇报不把系统描述成“预测真实社会的黑箱”。更准确的定位是：在边界明确、过程可追踪、输入可审计的条件下，构造一个可重复的数字舆情实验场，用于比较官方回应方案、复盘历史过程和发现机制性风险。

### 内容比例

- 第一部分“现实机制如何被模拟”：约 60% 至 65%。
- 第二部分“系统如何实现”：约 35% 至 40%。
- 推荐 30 页正文，汇报时长约 25 至 35 分钟。
- 如果需要压缩到 20 页，可合并第 7 与第 8 页、第 14 与第 15 页、第 22 与第 23 页、第 27 与第 28 页，并把第 29 页移入附录。

### 全篇主结论

> 系统的价值不在于让所有 Agent 复述同一种结论，而在于让异质个体在不同信息可见范围、历史记忆和干预条件下产生可解释的差异，并把这种差异的形成过程完整保存下来。

## 第一部分：现实机制如何被模拟

### 第 4 页：现实舆情不是一条曲线

**标题**  
现实舆情由事件、人群、信息、关系、组织和时间共同构成

**页面要点**

- 事件提供事实背景和持续变化的客观条件。
- 人群带来兴趣、立场、情绪表达和信息取向差异。
- 社交关系决定个体能够接触哪些观点。
- 评论把个体反应转化为可再次传播的公共信息。
- 官方通告在特定时间进入，改变可用证据和讨论对象。
- 时间让记忆、惯性、重复传播和阶段转换成为可能。

**建议图示**

六边形机制图。中心是“舆情状态”，外围六个要素分别连向中心。

**讲解重点**

负面率只是一种观测结果，不是系统本体。系统首先模拟形成负面率的过程，再统计曲线。

### 第 5 页：现实过程到仿真对象的映射

**标题**  
系统把社会过程拆成外生条件、内生行为和观测指标

**页面要点**

| 现实要素 | 仿真对象 | 性质 |
| --- | --- | --- |
| 已发生事件、公开事实 | 事件输入、逐轮公众语境 | 外生条件 |
| 官方公告 | 官方声明时间线或内容策略 | 外部干预 |
| 个体差异 | Persona | 稳定弱先验 |
| 关注关系 | 固定社交网络 | 实验结构 |
| 情绪、态度、评论意愿 | Agent 决策 | 内生状态 |
| 评论与转发 | 评论池、邻居曝光、表达谱系 | 内生传播 |
| 人工历史趋势 | 真实趋势参考 | 事后对照 |

**建议图示**

三层泳道图：输入条件、模拟过程、结果观测。

**讲解重点**

### 第 9 页：信息不对称如何产生

**标题**  
同一轮中，每个 Agent 看到的评论并不相同

**页面要点**

- 每个 Agent 固定关注 5 个其他 Agent。
- 每轮个人可见范围默认包含 11 条公共评论和 4 条邻居评论。
- 邻居评论来自上一轮真实表达，不是从全池随机伪造。
- 网络种子固定为 2026，使不同策略共用同一关系结构。
- 影响力权重改变被抽中概率，不直接指定个体情绪。

**建议图示**

以同一中心事件展示 A、B 两个 Agent 的不同可见评论集合。不要画成所有节点两两相连。

**讲解重点**

这是“信息茧房”和局部舆论环境的最小实现。网络边表示关注和接收关系，不代表本轮一定发生传播。

**技术依据**

- `demo/config/social_network_config.json`
- `demo/simulation/social_network.py`
- `demo/simulation/propagation.py`

### 第 10 页：看见、相信和表达是三件事

**标题**  
Agent 决策被拆成认知状态与公开行为

**页面要点**

1. 看见：从公共评论和邻居表达中形成个人可见信息。
2. 判断：选择当前情绪和对官方声明的态度。
3. 决定表达：判断本轮是否评论及表达派系。
4. 选择表达：只从个人可见、尚未重复发表的候选评论中选取。

**建议图示**

四阶段漏斗。每层都允许数量减少，体现“曝光不等于采纳，采纳不等于表达”。

**讲解重点**

现实中沉默也是行为。Agent 可以看到一条评论但不认同，也可以认同却不发表评论。

**技术依据**

- `demo/agents/decision_service.py`
- `demo/agents/decision_engine.py`

### 第 11 页：情绪与官方态度相互独立

**标题**  
接受官方结论，不等于对事件后果产生正面情绪

**页面要点**

- 情绪选项：正面、中性、负面。
- 官方态度选项：接受、观望、质疑，无公告时为不适用。
- Agent 可以“接受声明但仍因悲剧结果保持负面”。
- Agent 也可以“质疑声明但以中性方式等待证据”。
- 官方信息状态 `clear` 只表示信息完整度，不等于全体 Agent 必须接受。

**建议图示**

二维象限。横轴为官方态度，纵轴为事件情绪，每个象限给一个自然语言例子。

**讲解重点**

这是防止群体机械转向的关键设计。情绪衡量的是对事件及其后果的反应，官方态度衡量的是对声明可信度和回应价值的判断。

### 第 12 页：负面事件也允许正面表达

**标题**  
正面情绪必须有建设性语义，而不是赞同负面事件

**页面要点**

- 负面事件不再把 Agent 限制为中性或负面。
- 正面可以表示对搜寻、互助、事实澄清、公开回应或社会改进的希望与认可。
- 正面决策必须引用当前轮可用的正面证据编号。
- 对伤害、死亡或悲剧后果本身的赞同始终不允许标记为正面。
- 该机制扩大合理表达空间，同时保留语义约束。

**建议图示**

用“允许 / 不允许”的语义样例卡片，不展示敏感原始评论全文。

**讲解重点**

设计目标不是人为增加正面率，而是避免事件标签提前替 Agent 做结论。

**技术依据**

- `demo/agents/decision_engine.py`
- `demo/simulation/evidence_policy.py`

### 第 13 页：时间、记忆和证据优先级

**标题**  
上一轮状态形成惯性，当前轮新证据决定是否改变

**页面要点**

- Agent 保存上一轮情绪、官方态度、表达意愿和个人评论历史。
- 本轮首次出现的官方通告和新生成评论具有更高证据优先级。
- 持续声明只是背景，不应每轮都被当成新公告。
- 历史转发说明旧观点仍有热度，但不等于出现新事实。
- 当前历史回放使用最近 2 轮活跃舆情观察窗口。

**建议图示**

时间轴上区分“新增证据”“持续背景”“历史记忆”，并标出证据强弱。

**讲解重点**

状态不是简单复制。维持上一轮情绪也必须指出当前仍然存在的证据。

### 第 14 页：舆情如何内生演化

**标题**  
Agent 的公开表达会成为下一轮其他人的信息环境

**页面要点**

- 第一轮从 60 条初始评论构成公共讨论基线。
- 后续轮次生成与当轮事件和公告相关的增量评论。
- Agent 本轮选中的表达写入历史，并可在下一轮沿关注网络传播。
- 评论池同时保留新生成、历史兜底和本地应急来源标记。
- 系统分别观察当前轮、累计存量和最近窗口，避免混淆分母。

**建议图示**

闭环图：评论池 → 个体可见评论 → Agent 决策 → 实际表达 → 下一轮评论环境。

**讲解重点**

舆情不是每轮独立生成的一组随机文本。过去表达会留下存量并继续传播，但“当前轮新增”与“历史累计”必须分开解释。

### 第 15 页：网络传播如何被记录

**标题**  
传播被拆成邻居曝光与继续表达两个事件

**页面要点**

- `neighbor_exposure` 表示邻居表达进入目标 Agent 的可见范围。
- `was_selected=true` 才表示目标 Agent 继续表达该评论。
- 第一跳深度为 1，后续按最短已知谱系增加。
- 有效传播权重按 `影响力 × 0.7^(深度-1)` 衰减。
- 公共评论抽样不是关注关系传播，不计入传播链。

**建议图示**

一条 4 跳评论传播 DAG。将“看见但未转发”画成灰色虚线，将“继续表达”画成高亮实线。

**讲解重点**

社交网络图中的节点可以显示但没有高亮连线，因为它属于固定网络，却未参与当前选中 Agent 的本轮传播路径。

**技术依据**

- `demo/simulation/propagation_tracking.py`
- `demo/evaluation/propagation_metrics.py`
- `demo/docs/DATA_CONTRACT.md`

### 第 16 页：官方回应被建模为外部干预

**标题**  
官方信息改变的是可用证据，不是直接修改 Agent 状态

**页面要点**

- 公告包含原文、首次投入轮次和信息完整状态。
- 公告先进入事件状态，再由 Agent 结合 Persona 与可见评论判断。
- 系统不使用“发布公告后负面率自动下降”的硬编码。
- 公告效果可以滞后，也可能引发新的质疑或讨论反弹。
- 同一内容在不同信息环境和网络结构下可能产生不同结果。

**建议图示**

展示“官方公告投入”后分成接受、观望、质疑三条路径，再分别连接到不同情绪与表达结果。

**讲解重点**

官方通告是证据，不是控制指令。这一思想应贯穿五策略实验和历史回放。

### 第 17 页：五策略实验回答什么

**标题**  
五策略实验用于比较“如果采用不同回应内容，会发生什么”

**页面要点**

- 不回应作为对照组。
- 四类回应内容：事实通报、共情安抚、辟谣澄清、处置进展。
- 负面阈值、趋势恶化和持续停滞共同决定动态进场时机。
- 所有策略共享进场前基线和同一网络快照。
- 进场后状态完全隔离，比较相对不回应场景的净效果。

**建议图示**

一条共享时间线在进场节点分叉为五条策略路径，突出“分叉前相同、分叉后独立”。

**讲解重点**

这是反事实实验。它不声称真实世界同时发生了五种回应，而是在控制共同条件后比较相对效果。

**技术依据**

- `demo/experiment_runner.py`
- `demo/official_response_options.json`

### 第 18 页：历史回放回答什么

**标题**  
条件化历史回放用于观察真实时间条件下的自然响应

**页面要点**

- 输入事件初始资料和第一轮人工情绪比例。
- 逐轮投入当时已经公开的事实、公众议题和建设性证据。
- 在真实发布时间投入官方通告原文。
- 第 2 轮以后不输入真实评论文本或真实情绪比例。
- Agent 由 LLM 结合 Persona、个人可见评论和上一轮状态直接判断。

**建议图示**

三条平行时间轴：客观事实、公众语境、官方通告。三者汇入每一轮 Agent 仿真。

**讲解重点**

它是“在历史条件下运行模型”，不是“强制模型复制历史曲线”。真实趋势只在运行完成后作为探索性参照。

**技术依据**

- `demo/historical_replay/replay_runner.py`
- `demo/historical_replay/public_context.py`
- `demo/historical_replay/events/<event_id>/`

### 第 19 页：两种实验模式的职责边界

**标题**  
五策略比较与历史回放共享内核，但回答不同问题

**页面内容**

| 维度 | 五策略实验 | 条件化历史回放 |
| --- | --- | --- |
| 研究问题 | 哪种回应内容相对更有效 | 历史条件下模型如何演化 |
| 官方信息 | 人工设计的四类策略 | 真实通告及真实发布时间 |
| 运行结构 | 共享基线后分叉五场景 | 单一时间线连续回放 |
| 真实趋势 | 不使用 | 仅作事后探索性对照 |
| 第一轮人工比例 | 不使用 | 用于初始评论环境 |
| 结果解释 | 相对策略效果 | 机制一致性与偏差诊断 |

**建议图示**

以一页清晰表格为主，不再叠加流程图。

**讲解重点**

共享模块的通用修复会影响两种模式，但历史事件输入不会进入五策略实验，五策略内容配置也不会进入历史回放。

### 第 20 页：如何评价模拟结果

**标题**  
评价需要同时观察状态、舆情、传播、质量和边界

**页面要点**

- Agent 层：三类情绪分布、官方态度、评论意愿。
- 舆情层：当前轮、累计存量、最近活跃窗口的评论分布。
- 干预层：负面峰值、累计负面量、恢复、反弹和相对对照净效果。
- 传播层：曝光、覆盖、继续传播率、传播深度和有效权重。
- 质量层：LLM 评论数、历史兜底、本地应急、警告轮次和请求性能。
- 历史对照层：方向一致性、阶段差异等探索性指标，不称为预测准确率。

**建议图示**

五层仪表板结构。中心不要只放一条“负面率”大曲线。

**讲解重点**

一条曲线接近真实数据，不代表内部机制正确。反过来，曲线不完全一致也不等于系统无效，需要结合传播、决策证据和数据质量解释。

### 第 21 页：当前现实性与局限

**标题**  
系统已经具备过程真实性，但仍不是完整社会数字孪生

**页面要点**

- 已实现：异质 Persona、个人信息范围、记忆、传播谱系、官方干预和逐轮证据。
- 仍简化：固定关注关系、离散情绪状态、有限 Agent 数量。

- LLM 的共同语言模式可能造成群体过度一致。
- 当前没有用结果级配额或熔断强行改写群体分布。
- 下一阶段应优先验证机制稳健性，而不是追求单次曲线贴合。

**建议图示**

“已经实现 / 当前简化 / 下一步校准”三列成熟度图。

**讲解重点**

设计上宁可暴露群体坍缩问题，也不在结果层偷偷调整比例。问题应通过输入证据、个体差异、决策机制和多批次统计解决。

### 第 26 页：单轮仿真如何执行

**标题**  
每一轮都按照固定事务顺序推进并保存状态

**页面要点**

1. 更新事件阶段、公众语境和官方声明。
2. 生成本轮增量评论。
3. 根据固定网络构造每个 Agent 的个人可见评论。

### 附录 D：术语解释

- 邻居评论：沿固定关注关系进入个人可见范围的上一轮表达。
- 曝光：评论进入 Agent 可见范围。
- 继续传播：Agent 选择该评论作为本轮实际表达。
- 当前轮舆情：本轮新增或活跃评论的分布。
- 累计舆情：从第一轮到当前轮的评论存量分布。
- 条件化历史回放：在真实时间条件下运行模型，但不把后续真实情绪答案注入模型。

## 四、交给 PPT 制作 AI 的设计说明

### 视觉风格

- 延续第一次汇报的蓝白专业风格，可增加青色作为“模拟”、橙色作为“真实参考”、紫色作为“Agent 状态”。
- 每页只表达一个结论，标题直接写结论，不使用“功能介绍”“技术说明”一类空标题。
- 正文每页控制在 3 至 6 个短要点，详细解释放入演讲者备注。
- 流程关系优先使用图，精确模式差异优先使用表格，时间变化优先使用折线图或时间轴。
- 不要在同一页同时放大段代码、流程图和三张图表。
- 不使用无法追溯来源的装饰性 AI 图片作为技术证据。

### 素材优先级

1. 当前三层可视化页面截图。
2. 最新完成实验的趋势、网络和传播链截图。
3. 由代码结构绘制的原生矢量流程图。
4. 第一次汇报中的封面、机构标识和项目背景页。
5. 旧实验截图只能标注为“第一阶段结果”，不能替代当前数据。

### 数据表达规则

- 所有实验数字标注实验编号和运行日期。
- 区分 Agent 情绪、当前轮评论、累计评论和人工趋势参考。
- 第一轮人工比例标注为“初始条件”，不计入独立预测能力。
- 历史趋势比较使用“探索性对照”“阶段差异”“方向一致性”等表述。
- 不使用“模型准确预测社会舆情”“高度还原真实人群”等超出证据的结论。
- 对 `degraded` 批次必须同步展示评论质量和兜底情况。

### 建议从第一次汇报保留的内容

- 项目名称、汇报单位和整体视觉识别。
- 事件背景只保留一页，用于说明应用场景。
- “LLM 与确定性规则分工”的思想可以保留，但需要更新为当前受约束决策和证据校验机制。
- 原有胡某宇实验结果只作为第一阶段基线或问题来源，不直接当作第二阶段成果。

### 建议删除或重做的旧内容

- 旧版 10 个 Agent 或旧网络结构的结果截图。
- 把所有人展示为看到同一组评论的示意图。
- 把官方公告直接连接到负面率下降的确定性图示。
- 将人工趋势称为模型“准确率”的文字。
- 已被当前代码替代的旧历史回放、概率配额、群体熔断或单体可视化结构。

## 五、汇报人可直接使用的开场与收束

### 开场参考

第一次汇报中，我们证明了系统可以围绕一个突发事件生成评论、驱动 Agent 决策，并比较官方回应策略。第二阶段的重点不再是增加一条曲线，而是补足曲线背后的社会机制。我们需要回答：不同的人为什么看到不同的信息，为什么面对同一公告产生不同判断，一条评论如何在网络中继续传播，以及如何证明每一个结果来自哪些输入和过程。

### 收束参考

当前系统已经从流程演示进入机制实验阶段。它能够把异质个体、局部信息、历史记忆、网络传播和官方干预放入同一条可追踪时间线，也能够诚实暴露群体趋同和生成质量波动。下一阶段的研发目标不是人工修出一条更漂亮的曲线，而是通过多批次、跨事件和参数校准，确认这些机制是否稳定、可解释并具有比较价值。
