# 前端开发任务说明

更新日期：2026-09-07  
适用接口：`v1.1-product`

## 一、确定使用的技术栈

前端统一使用：

- `Vue 3`：页面和组件开发；
- `Vite`：本地开发、环境变量和生产构建；
- `Element Plus`：表单、按钮、表格、分页、标签、提示和弹窗等界面组件；
- `JavaScript`：业务代码，不使用TypeScript。

Vue 3应使用`Element Plus`，不是面向Vue 2的旧版Element UI。接口请求可直接使用浏览器`fetch`，如团队统一使用其他请求库，不能改变公共接口字段。第一版不强制引入Pinia、Axios或图表库；只有实际页面需要且团队同意时再增加依赖。

所有请求和响应字段必须遵守 `SHARED_INTERFACE_CONTRACT.md`，不能在不同页面分别创造字段名称。

### Element Plus主要用途

| 功能 | 建议组件 |
| --- | --- |
| 新建实验表单 | `el-form`、`el-input`、`el-select`、`el-button` |
| 状态和错误提示 | `el-tag`、`el-alert`、`el-result` |
| 实验列表 | `el-table`、`el-pagination` |
| 五策略切换 | `el-tabs`、`el-card` |
| 运行提示 | `el-dialog`、`el-skeleton`、`el-empty` |

评论弹幕、趋势图、社交网络图和传播路径属于业务可视化，使用Vue组件、CSS、SVG或经团队确认的轻量图表库实现，不把它们误做成Element Plus自带能力。

## 二、需要完成的两条用户流程

### 2.1 新建并观察实验

```text
填写事件
→ 填写四种官方声明
→ 检查输入
→ 提交实验
→ 查看运行状态
→ 成功后进入结果页
```

新建实验页面需要填写：

- `event_id`；
- 事件正文；
- 事件主题和正负属性；
- 动态进场规则与停滞参数；
- 事实通报、共情安抚、辟谣澄清和处置进展；
- 每条声明的 `clear/incomplete/conflict` 状态。

页面明确提示“不回应场景由系统自动加入”。第一版不提供Agent数、轮次、并发数和评论数设置。

提交成功后进入实验状态页。状态页每3～5秒请求一次A04：

- `pending`：等待运行；
- `running`：正在运行；
- `succeeded`：停止轮询，进入结果页；
- `failed`：停止轮询，显示简短错误和`request_id`。

不要显示后端没有提供的虚假完成百分比。

### 2.2 查询并查看历史实验

```text
打开实验列表
→ 按事件关键字或状态查询
→ 选择一次实验
→ 查看总体结果和详细数据
```

只有实验列表分页。其他页面不需要分页。

## 四、评论弹幕功能

评论不使用分页表格，使用固定弹幕区域。

需要实现：

- 选择策略场景；
- 选择全部轮次或某一轮；
- 按 `step` 顺序加入播放队列；
- 暂停、继续、重新播放和清空；
- 切换场景时清空旧队列；
- 控制同屏评论数量，避免遮挡；
- 显示评论正文，可选显示情绪或派系颜色；
- 同文本但不同 `comment_id` 的记录不由前端擅自删除。

前端可以一次获取整个场景评论，也可以使用 `?step=3` 只获取某轮评论。接口均直接返回数组。

## 五、结果页面展示规则

### 5.1 五策略比较

- 并列结果读取 `strategies[]` 和 `is_tie`；
- `is_tie=true`时显示全部并列策略；
- 不得只取一个策略暗示唯一最佳；
- `comparison=null`时显示“当前实验不可比较”。

### 5.2 逐轮趋势

- 横轴为`step`；
- 支持切换不同策略；
- 显示Agent负面率、官方质疑率、官方接受率；
- 标记官方进场轮次和原因；
- `null`表示不适用，不能画成0；
- 指标名称写“Agent负面率”，不能写“全社会负面率”。

### 5.3 数据质量

| 状态 | 页面解释 |
| --- | --- |
| `normal` | 评论生成质量正常 |
| `degraded` | 实验完成，但历史兜底较多 |
| `emergency` | 使用本地应急评论，结果需谨慎使用 |

兜底率统一显示为：

```text
fallback_count / (llm_comment_count + fallback_count)
```

分母为0时显示 `--`。

### 5.4 社交网络和传播

必须分开显示：

1. 关注关系：`source_agent_id → target_agent_id`表示source关注target；
2. 信息传播：`source_agent_id → target_agent_id`表示source向target暴露信息。

不能把两种方向混在一张图中。节点大小可以映射影响力权重。

## 六、接口和错误处理

- 所有接口统一解包`code/message/data/request_id`；
- 只有A03使用`page/page_size`；
- A06～A11直接读取数组或对象；
- `null`保持不适用语义；
- 404显示资源不存在；
- 409显示已有实验正在运行或输入冲突；
- 500显示简短错误和可复制的`request_id`；
- 任一接口失败都不能导致整个页面白屏；
- 浏览器中不能保存或请求DeepSeek Key。

## 七、做好之后是什么样

- 用户打开首页可以选择“新建实验”或“历史实验”；
- 输入事件和四种声明后，页面快速得到实验编号；
- 运行期间能看到明确状态，不需要一直停留在提交页面；
- 成功后可以查看5个场景及比较结果；
- 能查看逐轮曲线和进场轮次；
- 评论在固定区域以弹幕形式播放；
- 能查看质量、性能、关注网络和评论传播；
- 以前的实验可以通过分页列表重新打开；
- 错误、空数据和未运行状态都有明确页面提示。
