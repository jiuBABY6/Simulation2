# 三端本地测试与联调清单

更新日期：2026-09-07  
适用接口：`v1.1-product`

## 一、测试和推送顺序

```text
个人分支开发
→ 各负责人本地测试
→ 三端在本地联合测试
→ 修复P0问题
→ 再提交并推送个人分支
→ 创建Pull Request
→ 评审后合并main
```

个人分支推送前至少应是开发者本机验证通过的版本，不能默认推送后再让其他成员代替本人完成测试。

## 二、历史结果联调

统一使用：

```text
demo/experiments/event_gaoyang_assault_001_20260906_143939_040535
```

固定标识：

```text
event_id      = event_gaoyang_assault_001
experiment_id = event_gaoyang_assault_001_20260906_143939_040535
scenario_id   = fact_report
comment_id    = comment_066
```

联调步骤：

1. 数据库导入该实验；
2. 后端通过A03、A05～A11查询；
3. 前端从分页实验列表进入详情；
4. 检查5个场景和完整轮次；
5. 检查评论弹幕、数据质量、关注网络和传播查询；
6. 重复导入，确认没有重复数据；
7. 重启服务后重新查询。

## 三、新建实验联调

使用另外准备的简短公开测试事件和四种测试声明，不使用真实敏感材料。

联调步骤：

1. 前端填写事件和四种声明；
2. A02返回HTTP 202和`experiment_id`；
3. A04依次返回`pending/running`；
4. 运行期间再次提交实验，确认返回409；
5. 运行结束后状态变为`succeeded`或明确的`failed`；
6. 成功结果自动入库并出现在A03分页列表；
7. 前端可以直接进入结果页；
8. 原有 `python demo\main.py` 仍可独立运行。

## 四、数据库负责人通过条件

- 使用MySQL 8.0、InnoDB和utf8mb4；
- 空数据库可以通过建表SQL完成初始化；
- 新建实验可以保存输入和`pending`状态；
- 运行状态和结果状态能够分别更新；
- 旧实验可完整导入；
- 重复导入不重复写入；
- 实验结果导入失败时事务回滚；
- 中文、Emoji和JSON不乱码；
- 表中不保存密钥和本机绝对路径。

## 五、后端负责人通过条件

- 后端使用FastAPI和Pydantic，`/docs`能够展示公共接口模型；
- 请求、响应和状态枚举均经过Pydantic校验；
- A01～A12响应符合公共契约；
- A02快速返回，不阻塞到实验结束；
- 第一版同一时间只运行一个实验；
- 状态不会永久停在`running`；
- 只有实验列表分页；
- 评论、轮次、场景、网络、传播和Agent轨迹不分页；
- 失败响应不暴露完整堆栈和密钥；
- 自动化测试不调用真实LLM。

## 六、前端负责人通过条件

- 前端使用Vue 3、Vite、Element Plus和JavaScript，不使用TypeScript；
- Vite开发服务和生产构建均可完成；
- 首页只有清晰的“新建实验”和“历史实验”入口；
- 新建实验能够输入完整四策略；
- 状态页能停止轮询并正确跳转；
- 历史实验列表分页正常；
- 评论弹幕能按场景和轮次播放；
- `null`没有被错误显示为0；
- 并列策略、未运行和质量降级显示正确；
- 关注和传播方向正确；
- 接口失败不会白屏。

## 七、不能带着以下问题推送待合并版本

- 三端字段名称不一致；
- `run_status`和`result_status`混用；
- 场景或轮次数量错误；
- 比率单位错误；
- 除实验列表外又增加另一套分页结构；
- 评论弹幕一次性渲染全部评论导致页面卡顿；
- 关注或传播方向画反；
- 两个实验共用并覆盖输入或状态目录；
- 重复导入产生重复数据；
- 页面白屏或后端泄露敏感信息。

## 八、推送时需要提供什么

Pull Request写明：

- 完成了哪些功能；
- 本地启动方式；
- 测试步骤和结果；
- 页面截图或接口响应；
- 尚未完成的功能；
- 是否修改公共接口。

公共接口不能口头修改。确需调整时先更新 `SHARED_INTERFACE_CONTRACT.md`，三端确认后再修改代码。
