# 数据库、后端与前端开发任务说明

更新日期：2026-09-07  
接口版本：`v1.1-product`

本目录面向数据库、后端和前端开发成员，只说明需要完成的功能、完成后的效果和本地验收要求，不规定开发者必须使用的目录或文件结构。

## 一、统一技术栈

| 层级 | 确定使用的技术 | 主要职责 |
| --- | --- | --- |
| 数据库 | MySQL 8.0 | 保存实验输入、运行状态和仿真结果 |
| 后端 | FastAPI + Pydantic | 接收和校验输入、运行实验、提供查询API |
| 前端 | Vue 3 + Vite + Element Plus + JavaScript | 提供实验操作和结果展示页面 |

Vue 3对应的Element组件库使用`Element Plus`。前端不使用TypeScript；后端所有请求和响应都通过Pydantic模型校验。

## 二、系统要解决的两件事

### 1. 新建并观察实验

用户输入一个事件和四种官方回应声明，系统自动加入“不回应”场景，运行五策略对照实验。用户可以查看实验状态，完成后进入结果页面。

### 2. 查询历史实验

用户在分页实验列表中查找以前的实验，进入详情后查看策略比较、逐轮指标、评论弹幕、数据质量、社交网络和评论传播。

## 三、第一版需要具备的功能

| 功能 | 用户操作 | 完成后的效果 |
| --- | --- | --- |
| 新建实验 | 填写事件和四种官方声明并提交 | 系统生成实验编号并在后台运行 |
| 实验状态 | 查看等待、运行、成功或失败 | 长时间运行时页面不会一直无反馈 |
| 历史实验 | 按页查询以前的实验 | 可以重新打开任何已入库实验 |
| 结果总览 | 查看五策略和比较结果 | 能判断不同回应策略的模拟差异 |
| 逐轮趋势 | 切换策略查看指标曲线 | 能观察每轮舆情变化和进场时机 |
| 评论弹幕 | 在固定区域播放评论 | 能直观看到各轮评论内容变化 |
| 数据质量 | 查看兜底、告警和性能 | 能判断结果是否需要谨慎解释 |
| 社交网络 | 查看关注关系和影响力 | 能观察Agent之间的固定关系 |
| 传播分析 | 查询评论传播路径 | 能研究评论如何沿关系网络扩散 |
| 导入旧实验 | 导入已有实验目录 | 现有Demo结果可以进入新系统查询 |

事件和官方声明可以保存在数据库中供以后查看，但第一版不单独开发复杂的事件管理后台。

## 四、第一版不做的功能

- 单条声明的单场景演化模式；
- 内容策略与声明状态的完整排列组合；
- 多个实验同时运行；
- 登录、角色和权限管理；
- 删除历史实验；
- 适应性画像更新；
- 动态关注关系和传播参数校准。

## 五、三人分工

| 负责人 | 主要任务 | 最终交付结果 |
| --- | --- | --- |
| 数据库 | 使用MySQL保存输入、状态和结果，导入已有实验 | 后端可完全从MySQL读写业务数据 |
| 后端 | 使用FastAPI和Pydantic接收输入、串行运行仿真、提供API | 前端能启动实验并查询全部结果 |
| 前端 | 使用Vue 3、Vite、Element Plus和JavaScript实现两条流程 | 用户能新建实验或查询历史结果 |

## 六、统一规则

- 三端字段以 `SHARED_INTERFACE_CONTRACT.md` 为准；
- 只有实验列表分页，其他数据直接返回；
- 评论使用固定区域弹幕，不使用表格分页；
- 前端统一使用JavaScript和Element Plus，不使用TypeScript；
- 后端请求、响应和枚举统一使用Pydantic模型；
- 第一版同一时间只允许运行一个实验；
- 仿真核心算法继续复用 `demo`，后端不能复制算法；
- 原始实验文件继续保留，数据库作为业务查询层；
- 开发者先在本机测试，测试成功后才推送个人分支；
- Pull Request必须附测试步骤和结果。

## 七、统一本地测试样本

历史结果查询统一使用：

```text
demo/experiments/event_gaoyang_assault_001_20260906_143939_040535
```

```text
event_id      = event_gaoyang_assault_001
experiment_id = event_gaoyang_assault_001_20260906_143939_040535
scenario_id   = fact_report
comment_id    = comment_066
```

新实验运行测试由负责人另外准备一份简短事件和四种测试声明，不使用公安部门真实敏感材料。

## 八、文档阅读顺序

1. `SHARED_INTERFACE_CONTRACT.md`：统一字段和接口；
2. 本人负责的开发任务文档；
3. `INTEGRATION_CHECKLIST.md`：本地联调和推送条件。

任何公共接口变更都必须先修改统一契约，再同步数据库、后端和前端。
