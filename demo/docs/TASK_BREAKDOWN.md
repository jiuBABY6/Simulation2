# 团队任务拆分

本文档用于直接分配任务。每个任务负责人只能修改约定范围；需要跨模块变更时先更新接口文档并由仿真核心负责人确认。

## 任务A：配置安全与环境固化

目标：使新成员可以安全复现当前Demo。

负责范围：`project_config.py`、环境示例、依赖清单和运行文档。

验收条件：

- 代码中没有真实API密钥；
- 缺少密钥时给出明确报错；
- 新环境按照文档可以启动；
- 不改变仿真算法和实验结果字段。

## 任务B：数据库设计与导入

目标：保存现有JSON/JSONL实验数据并提供稳定查询。

第一版实体：事件、实验、官方策略、轮次、Agent、评论、Agent决策、Agent状态、轮次指标和性能记录。

验收条件：

- 可以导入一个已有实验目录；
- 导入后数量和原始文件一致；
- 保留原始JSON；
- 重复导入同一`experiment_id`不会产生重复数据；
- 不修改`demo`仿真核心。

## 任务C：后端实验接口

目标：提供事件配置、实验启动、运行状态和结果查询接口。

建议第一阶段使用任务子进程调用现有入口，不把仿真逻辑复制到后端。

验收条件：

- 能创建实验并返回`experiment_id`；
- 能查询运行中、成功、失败和未运行状态；
- 能读取策略比较、数据质量和性能摘要；
- 一个任务失败不会终止后端服务。

## 任务D：前端与可视化

目标：把现有只读页面扩展为实验管理和结果展示界面。

验收条件：

- 能选择事件和查看实验列表；
- 能展示逐轮趋势、策略比较、数据质量和耗时；
- 明确区分Agent指标与评论池指标；
- 不直接修改实验目录中的结果文件。

## 任务E：仿真验证与基线维护

目标：维护标准事件、联调记录和性能回归口径。

验收条件：

- 保持统一Agent数、轮数、评论数和随机种子；
- 按实际执行增量轮次去重计算兜底率；
- 记录单位增量轮次耗时，而不是只比较总耗时；
- 每次正式联调追加到`INTEGRATION_TEST_HISTORY.md`。

## 后续扩展任务

适应性画像、社交网络、Agent影响力、固定进场时机和声明状态组合实验暂不与数据库、后端第一阶段混合开发。扩展模块必须通过接口接入，不得直接改写历史实验数据。
