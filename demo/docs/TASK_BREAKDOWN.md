# 团队任务拆分

本文档用于直接分配任务。每个任务负责人只能修改约定范围；需要跨模块变更时先更新接口文档并由仿真核心负责人确认。

数据库、后端和前端需要完成的功能、公共接口、完成效果和本地验收标准见`dev/README.md`及其三份负责人文档。

## 任务A：配置安全与环境固化

目标：使新成员可以安全复现当前Demo。

负责范围：`project_config.py`、环境示例、依赖清单和运行文档。

当前状态：根目录依赖清单和环境变量读取机制已经建立；后续只需随依赖变化维护清单，并在每次提交前执行密钥检查。

验收条件：

- 代码中没有真实API密钥；
- 缺少密钥时给出明确报错；
- 新环境按照文档可以启动；
- 不改变仿真算法和实验结果字段。

## 任务B：数据库设计与导入

目标：保存新实验的输入与运行状态，导入现有JSON/JSONL实验数据并提供稳定查询。

第一版使用`dev/DATABASE_DEVELOPMENT.md`确定的11张MVP表，运行状态直接保存在实验表中。

验收条件：

- 可以导入一个已有实验目录；
- 导入后数量和原始文件一致；
- 保留原始JSON；
- 重复导入同一`experiment_id`不会产生重复数据；
- 不修改`demo`仿真核心。

## 任务C：后端实验接口

目标：提供事件配置、实验启动、运行状态和结果查询接口。

建议第一阶段使用任务子进程调用现有入口，不把仿真逻辑复制到后端。

验收条件：

- 能创建实验并返回`experiment_id`；
- 能查询运行中、成功、失败和未运行状态；
- 能读取策略比较、数据质量和性能摘要；
- 一个任务失败不会终止后端服务。

## 任务D：前端与可视化

目标：把现有只读页面扩展为实验管理和结果展示界面。

验收条件：

- 使用Vue 3和JavaScript输入事件及四种声明，并查看分页实验列表；
- 能展示逐轮趋势、策略比较、数据质量和耗时；
- 能在固定区域以弹幕形式播放评论；
- 明确区分Agent指标与评论池指标；
- 不直接修改实验目录中的结果文件。

## 任务E：仿真验证与基线维护

目标：维护标准事件、联调记录和性能回归口径。

验收条件：

- 保持统一Agent数、轮数、评论数和随机种子；
- 按实际执行增量轮次去重计算兜底率；
- 记录单位增量轮次耗时，而不是只比较总耗时；
- 每次正式联调追加到`INTEGRATION_TEST_HISTORY.md`。

## 后续扩展任务

固定社交网络、Agent影响力、邻居评论传播和个人可见范围内表达已经完成第一阶段实现；传播事件持久化、表达谱系、层级与衰减、覆盖与深度指标已经通过第二十六次正式五策略联调，第二阶段A完成验收。动态关注关系和参数校准继续作为第二阶段B任务。适应性画像、固定进场时机和声明状态组合实验暂不与数据库、后端第一阶段混合开发。扩展模块必须通过接口接入，不得直接改写历史实验数据。
